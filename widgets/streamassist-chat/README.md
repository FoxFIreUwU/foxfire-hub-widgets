# Чат StreamAssist (Twitch + YouTube) — `streamassist-chat`

Отдельный виджет FoxFire Hub. Это чат из программы **StreamAssist**, вынесенный в Hub: тот же код отрисовки и те же настройки.
Он **не заменяет** виджет `unified-chat` («Общий чат») — это самостоятельный виджет со своим `id`, своей версией (`1.0.0`)
и своими настройками; оба можно держать установленными одновременно.

## Что внутри

| Файл | Откуда | Что делает |
|---|---|---|
| `wstyle.js`, `wchat.js`, `wpanel.js` | StreamAssist (`frontend/js/`), **без изменений** | формат стиля, отрисовка чата, панель настроек |
| `sachat-hub.js` | новый | Twitch (анонимный IRC), 7TV/BTTV, YouTube, единый формат сообщения — то, что в StreamAssist делает Rust |
| `index.html` | собирается `tools/build.py` | страница виджета (скрипты вшиты): окно в Hub и прозрачный оверлей для OBS |
| `settings.html` | собирается `tools/build.py` | встроенные настройки (скрипты вшиты): подключение, предпросмотр, ссылка для OBS, панель оформления |
| `foxfirehub-bridge.js`, `config.js` | как у `unified-chat` | мост с Hub и файл настроек (его перезаписывает Hub) |
| `tests/` | StreamAssist + новые | 41 проверка (`node --test tests/wstyle.test.js tests/sachat-hub.test.js`, нужен Node 18+) |

`wstyle.js` / `wchat.js` / `wpanel.js` лежат здесь копиями. Если в StreamAssist поменяется оформление чата, достаточно
скопировать эти три файла заново — `sachat-hub.js` их не трогает.

## Как это работает

- Настройки оформления (~130 полей) и подключения хранит Hub в `foxfire-state.json`; `settings.html` шлёт их через
  `foxfirehub:settings-saved`, а Hub пишет `config.js` рядом с `index.html`. Ссылка в OBS постоянная.
- Хранятся только отличия от умолчаний — старые сохранения не ломаются при добавлении полей.
- Twitch читается без токена. YouTube: «Без ключа (через Hub)» — через локальный сервер Hub (`/api/yt/poll`) или команду
  `yt_chat_poll`, как у `unified-chat`; запасной режим — официальный API-ключ Google (кнопка «Проверить ключ»).
- Размытие фона (`backdrop-filter`) работает только в окне Hub. В OBS оно рисует чёрный блок, поэтому там отключено.
- Текст чата никогда не вставляется как HTML — только `textContent`; картинки только по `https://`.

## Известные ограничения

- Чтение YouTube без ключа — неофициальный способ, YouTube может его сломать; тогда используйте API-ключ.
  Rust-часть Hub для него (`youtube_chat.rs`, `local_server.rs`) по заявлению автора не проверялась на живом эфире —
  это относится и к этому виджету.
- Смайлы 7TV/BTTV — только глобальные наборы (смайлы конкретного канала требуют Twitch API).
- Настоящих аватарок зрителей нет: «аватар» — значок площадки или первая буква ника.
- Ссылка `file://` (если у Hub нет локального сервера) работает для Twitch, но не для YouTube без ключа.
- Hub должен быть запущен, пока идёт стрим.

## Публикация

Как в `HOW_TO_PUBLISH_REGISTRY.md`: заархивировать содержимое этой папки (без `tests/` и `screenshots/`) в
`streamassist-chat.zip`, создать релиз `streamassist-chat-v1.0.0` и прикрепить архив — ссылка уже прописана в
`widget.manifest.json` и `registry.json`. Новая версия — новый объект в `versions[]`, `id` не меняется.

## Сборка страниц

`index.html` и `settings.html` — готовые файлы со вшитыми скриптами: внутри Hub страница настроек открыта во вложенном окне,
и Tauri не отдаёт ей соседние файлы, поэтому подгрузка `<script src>` там не работает (так было в версии 1.0.0).
Правите `.js` или `tools/*.template.html` — запустите `python3 tools/build.py`. Папка `tools/` в архив релиза не входит.
