# Общий чат (Twitch + YouTube)

Склеивает чаты Twitch и YouTube в одну общую ленту, отсортированную по времени —
удобно и стримеру (не бегать глазами между двумя окнами), и зрителям (оверлей
поверх стрима показывает сообщения с обеих площадок одной линией).

**В версии 2.0.0**: не нужно каждый эфир вручную копировать Video ID YouTube —
достаточно один раз указать канал, дальше трансляция находится автоматически.
Плюс встроенная страница настроек с живым предпросмотром (открывается прямо
внутри FoxFire Hub, во вкладке "Загруженное" — без отдельного окна), SVG-иконки
бейджей, выбор шрифта, анимации, гибкая стилистика, действия модераторов и
сторонние Twitch-эмоуты (7TV, BetterTTV). Подробности — ниже.

## Быстрый старт

1. Установи виджет из FoxFire Hub, открой его настройки.
2. Впиши логин канала Twitch (если стримишь туда) — токен не нужен.
3. Впиши канал YouTube (ссылку, `@handle` или ID канала) и свой бесплатный
   API-ключ YouTube Data API v3 (как получить — см. ниже).
4. Всё, дальше ничего обновлять вручную не надо: пока идёшь на YouTube-эфир,
   виджет сам находит текущую трансляцию.

## Настройки с предпросмотром

Во вкладке "Загруженное" в FoxFire Hub выбери «Общий чат (Twitch + YouTube)»
слева — справа откроется `settings.html`: слева форма, справа сразу видно, как
будет выглядеть лента (по умолчанию — с демо-сообщениями, чтобы можно было
настроить стиль даже без реального эфира). Настройки сохраняются сразу, по
мере ввода — отдельно нажимать "Сохранить" не обязательно. Там же кнопка
**«Скопировать ссылку для OBS»** — готовая ссылка с текущими настройками,
которую остаётся вставить в источник "Браузер".

## Настройка Twitch (не требует токена)

Просто впиши логин канала в поле «Логин канала Twitch». Виджет подключается к
чату анонимно (стандартный приём `justinfanXXXXX`, которым пользуются почти
все сторонние Twitch-виджеты) — свой аккаунт или OAuth не нужны, достаточно
того что канал публичный.

## Настройка YouTube

У YouTube, в отличие от Twitch, нет анонимного протокола чтения чата —
единственный официальный способ без своего сервера-бэкенда — это
**YouTube Data API v3** с собственным API-ключом. Получить ключ можно
бесплатно за 5 минут:

1. Зайди на https://console.cloud.google.com/ и создай новый проект (или
   выбери существующий).
2. В разделе "APIs & Services" → "Library" найди **YouTube Data API v3** и
   нажми "Enable".
3. В разделе "APIs & Services" → "Credentials" нажми "Create Credentials" →
   "API key".
4. Скопируй полученный ключ — это значение для поля «API-ключ YouTube».
   *(Рекомендуется в настройках ключа ограничить его по API — "Restrict key" →
   только YouTube Data API v3 — на всякий случай, чтобы им нельзя было
   воспользоваться для чего-то другого, если он утечёт.)*
5. В поле «Канал YouTube» впиши ссылку на канал, `@handle` или ID канала
   (`UC...`) — один раз, дальше трогать не нужно.

### Как теперь находится трансляция

- **Внутри FoxFire Hub** — бесплатно и без квоты: виджет спрашивает у самого
  приложения (через Rust, в обход CORS) обычную ссылку вида
  `youtube.com/@channel/live` и смотрит, на какой адрес был редирект — ровно
  то же самое, что видит человек, кликая "Live" на канале. Это не Data API и
  квоту ключа не расходует. Проверяется каждые ~20 секунд, пока эфира нет.
- **Как отдельный файл (например, в источнике "Браузер" в OBS, без FoxFire
  Hub рядом)** — таким способом читать `youtube.com/.../live` браузер не даёт
  (CORS), поэтому используется резервный вариант через официальный
  `search.list` с твоим ключом. Он ощутимо дороже по квоте (100 единиц за
  проверку), поэтому опрашивается редко — раз в 5 минут, пока трансляции нет.
  После того как трансляция найдена, само чтение сообщений идёт как обычно и
  дёшево (~1–5 единиц за опрос).
- **Если ничего из этого не подошло** — есть запасное поле «Video ID вручную»:
  впиши его, и виджет вообще не будет ничего искать сам, а сразу подключится
  к указанному видео (это старое поведение версии 1.0.0, оставлено как
  страховка).

Если квота ключа закончится (лимит Google по умолчанию — 10 000 единиц в
день) — YouTube-часть ленты просто перестанет получать новые сообщения до
следующего дня или пока не создашь новый ключ; Twitch-часть при этом
продолжит работать как обычно.

## Персонализация

- **Шрифт** — набор безопасных вариантов (гарантированно есть у всех) плюс
  «Свой шрифт...», где можно вписать название шрифта со своего ПК (с
  fallback на системный, если у зрителя этого шрифта нет).
- **Анимация** появления сообщений — плавно, снизу вверх, слева или без
  анимации.
- **Стилистика** — масштаб, размер шрифта, отступы между сообщениями,
  скругление углов, прозрачность фона карточки, цвет текста и отдельный
  акцентный цвет (суперчаты, рамки, скроллбар).
- **Бейджи и иконки площадок** — теперь SVG (не эмодзи), меняют цвет вместе
  с темой.
- **Действия модераторов** — таймауты, баны и удаление сообщений в Twitch-чате
  показываются отдельной строкой (можно выключить).
- **Сторонние эмоуты Twitch** — глобальные наборы 7TV и BetterTTV
  подставляются в текст сообщений в дополнение к нативным Twitch-эмоутам.
  Наборы конкретного канала (не глобальные) пока не поддержаны — для их
  загрузки нужен числовой Twitch ID канала, а его официально можно узнать
  только через Twitch Helix API с client-id/токеном, то есть уже не совсем
  анонимное подключение; оставлено на будущее.

## Параметры (query-string у index.html)

Та же схема, что и в `configSchema` виджета — этим же способом виджет
получает настройки при запуске как файла (OBS), а `settings.html` передаёт их
живьём через postMessage при редактировании.

| Параметр | Что делает | По умолчанию |
|---|---|---|
| `twitchChannel` | Логин канала Twitch | *(пусто)* |
| `youtubeChannel` | Канал YouTube — ссылка, `@handle` или ID | *(пусто)* |
| `youtubeApiKey` | Твой API-ключ YouTube Data API v3 | *(пусто)* |
| `youtubeVideoIdOverride` | Video ID вручную (запасной вариант) | *(пусто)* |
| `direction` | `Новые снизу` / `Новые сверху` | `Новые снизу` |
| `fontFamily` | Шрифт из списка или `Свой шрифт...` | `Системный (по умолчанию)` |
| `fontFamilyCustom` | Название своего шрифта, если выбрано «Свой шрифт...» | *(пусто)* |
| `animationStyle` | Анимация появления сообщений | `Плавно (fade)` |
| `scale` | Общий масштаб, % | `100` |
| `fontSize` | Размер шрифта, px | `18` |
| `messageSpacing` | Отступ между сообщениями, px | `6` |
| `cornerRadius` | Скругление углов карточки, px | `16` |
| `maxMessages` | Сколько последних сообщений держать на экране | `40` |
| `bgOpacity` | Непрозрачность фона карточки, % | `55` |
| `showPlatformIcons` | Показывать SVG-значок площадки | `true` |
| `showBadges` | Показывать SVG-бейджи | `true` |
| `showTimestamps` | Показывать время сообщения | `false` |
| `highlightModActions` | Показывать таймауты/баны/удаления | `true` |
| `enableThirdPartyEmotes` | Глобальные эмоуты 7TV/BetterTTV | `true` |
| `textColor` | Цвет текста сообщений | `#f4f0ea` |
| `accentColor` | Акцентный цвет (суперчаты, рамки, скролл) | `#e2820a` |

Можно использовать только одну площадку — просто оставь поля второй пустыми.

## Для следующего агента / интеграция с Hub

Начиная с версии Hub 0.1.6 эта интеграция уже полностью реализована и работает —
описываю здесь, как именно, на случай доработок.

`settings.html` открывается не в отдельном окне, а прямо внутри FoxFire Hub, во
вкладке **"Загруженное"** (список установленных виджетов слева, настройки выбранного
справа) — в обычном `<iframe>`. За это отвечает поле `"settingsEntry": "settings.html"`
в `widget.manifest.json`, указанное для версии `2.0.0` (у версии `1.0.0` его нет — она
по-прежнему получает старую автоформу Hub по `configSchema`, это и есть пример того,
как одна версия виджета поддерживает встроенные настройки, а другая нет).

Начальный конфиг страница получает как обычно — через query-параметры своего URL.
Сохранение (при каждом изменении поля — живьём, и повторно по кнопке "Сохранить")
идёт через `window.parent.postMessage({ type: "foxfirehub:settings-saved", widgetId:
"unified-chat", config }, "*")` — см. функцию `notifyHubEmbedded` в `settings.html`.
Полный контракт для новых виджетов — `SYSTEM_WIDGET_STYLE.md` в корне `foxfire-hub`,
раздел 11.

Старый способ через Tauri-событие `unifiedchat:settings-saved` оставлен в коде как
запасной вариант — сработает, только если когда-нибудь `settings.html` откроют в
отдельном окне (`window.parent === window`, но доступен `window.__TAURI__`), что
текущий Hub уже не делает.

Также добавлена Rust-команда `resolve_youtube_live_video` в
`src-tauri/src/main.rs` самого Hub (и включён `withGlobalTauri: true` в
`tauri.conf.json`) — без этого бесплатный авто-поиск трансляции внутри Hub
работать не будет, поэтому при обновлении виджета не забудь пересобрать сам
Hub, а не только этот виджет.

## Известные ограничения

- Наборы эмоутов 7TV/BetterTTV конкретного канала не поддержаны — только
  глобальные (см. раздел «Персонализация» выше).
- Кастомные эмодзи участников YouTube (channel member emoji) в Data API не
  отдаются как картинки — показываются как обычный текст сообщения.
- При очень активном чате и маленькой дневной квоте ключа YouTube-сообщения
  могут приходить с задержкой — Twitch на это не влияет и продолжает работать
  в реальном времени.
- Бейджи показаны как узнаваемые нейтральные SVG-глифы (корона, щит, звезда и
  т.д.), а не точные официальные картинки бейджей Twitch/YouTube.
