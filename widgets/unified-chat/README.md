# Общий чат (Twitch + YouTube)

Склеивает чаты Twitch и YouTube в одну общую ленту, отсортированную по времени —
удобно и стримеру (не бегать глазами между двумя окнами), и зрителям (оверлей
поверх стрима показывает сообщения с обеих площадок одной линией).

## Как использовать вручную (до установки из FoxFire Hub)

1. Скачай `index.html` из этой папки.
2. Открой его в браузере с нужными параметрами (см. ниже) — или сразу вставь
   готовую ссылку с параметрами в источник "Браузер" в OBS.
3. Настрой размер источника под свою сцену.

## Настройка Twitch (не требует токена)

Просто впиши логин канала в параметр `twitchChannel`, например `twitchChannel=my_channel`.
Виджет подключается к чату анонимно (стандартный приём `justinfanXXXXX`, которым
пользуются почти все сторонние Twitch-виджеты) — свой аккаунт или OAuth не нужны,
достаточно того что канал публичный.

## Настройка YouTube — два режима на выбор

У YouTube, в отличие от Twitch, нет анонимного протокола чтения чата — читать
его без своего сервера-бэкенда можно только через **YouTube Data API v3**.
Виджет поддерживает два способа это сделать — выбираются параметром `youtubeMode`.

### Режим 1. "Вручную (Video ID + ключ)" — проще всего завести

1. Зайди на https://console.cloud.google.com/ и создай новый проект (или выбери
   существующий).
2. В разделе "APIs & Services" → "Library" найди **YouTube Data API v3** и нажми
   "Enable".
3. В разделе "APIs & Services" → "Credentials" нажми "Create Credentials" → "API key".
4. Скопируй полученный ключ — это значение для параметра `youtubeApiKey`.
   *(Рекомендуется в настройках ключа ограничить его по API — "Restrict key" →
   только YouTube Data API v3 — на всякий случай, чтобы им нельзя было
   воспользоваться для чего-то другого, если он утечёт.)*
5. Перед каждым эфиром скопируй **Video ID** своей трансляции — это часть ссылки
   после `watch?v=`, например для `https://www.youtube.com/watch?v=dQw4w9WgXcQ`
   это `dQw4w9WgXcQ` — вставь в параметр `youtubeVideoId`.

Video ID меняется на каждой новой трансляции, его нужно обновлять вручную —
виджет специально не ищет активную трансляцию по имени канала, так как такой
поиск (`search.list`) стоит намного дороже дневной квоты ключа, чем обычный опрос
чата.

### Режим 2. "Вход через Google (авто)" — без Video ID, но с настройкой один раз

Этот режим сам находит текущую активную трансляцию канала и её чат — Video ID
вписывать не нужно вообще, ни разу. Работает через **Device Code Flow** — тот же
механизм, которым Google авторизует приложения на телевизорах и игровых
консолях без полноценного браузера с адресной строкой (обычная кнопка
"Войти через Google" тут не подходит — ей нужен настоящий `https://`-адрес
источника, а у виджета в OBS его нет, это просто локальный файл).

Настройка (один раз, не на каждый стрим):

1. Зайди на https://console.cloud.google.com/ и создай новый проект (или
   используй тот же, что и для режима 1).
2. В "APIs & Services" → "Library" включи **YouTube Data API v3** (как в
   режиме 1, шаг 2).
3. Открой "APIs & Services" → "Credentials" → "Create Credentials" →
   "OAuth client ID".
4. Если попросит — настрой "OAuth consent screen" (тип **External**,
   заполни только обязательные поля, для личного использования публиковать
   приложение не обязательно — работает и в статусе "Testing", просто добавь
   свой Google-аккаунт в список тестовых пользователей на этом экране).
5. Тип приложения (Application type) выбери **"TVs and Limited Input devices"**
   — этот тип специально не требует client secret, что и позволяет
   пользоваться им прямо из статического файла без сервера.
6. Скопируй получившийся **Client ID** — это значение для параметра
   `googleClientId`. Client secret не нужен и не появится для этого типа.
7. Поставь `youtubeMode=Вход через Google (авто)`.

При запуске виджет покажет прямо на экране: *"откройте google.com/device и
введите код XXXX-XXXX"* — открой эту страницу на телефоне или другом
устройстве, войди под тем же Google-аккаунтом, что владеет YouTube-каналом, и
введи код. Дальше виджет сам сохранит вход (в локальном хранилище браузера/
источника OBS) и будет сам находить текущий активный эфир при каждом
запуске — заново входить не нужно, пока не очистишь данные этого источника.

**Важная техническая оговорка:** это два прямых запроса к серверам Google
(`oauth2.googleapis.com`) прямо со страницы виджета, без своего сервера-
посредника. Технически такой флоу для этого и придуман (устройства без
нормального браузера), но Google явно не документирует и не гарантирует,
что разрешит эти запросы из произвольного места без ограничения по
происхождению (CORS). Мы это реализовали и оно должно работать, но если в
вашем конкретном OBS/окружении вход не пройдёт (виджет покажет текст ошибки
вместо кода) — просто переключитесь на режим 1 ("Вручную"), он гарантированно
рабочий и не зависит от этого нюанса.

Учти также: OBS-источник "Браузер" и окно самого FoxFire Hub — это разные
браузерные контексты с разным локальным хранилищем, поэтому войти через Google
нужно будет отдельно в каждом месте, где реально используешь виджет (например,
отдельно в OBS и отдельно при тестовом просмотре в самом Hub).

### Квота API (общее для обоих режимов)

Лимит Google по умолчанию — 10 000 единиц в день, опрос чата стоит 5 единиц за
запрос, интервал опроса виджет сам подстраивает под рекомендацию самой YouTube
API, лишний раз не долбит сервер. Если квота закончится — YouTube-часть ленты
просто перестанет получать новые сообщения до следующего дня; Twitch-часть при
этом продолжит работать как обычно.

## Параметры (query-string у index.html)

| Параметр | Что делает | По умолчанию |
|---|---|---|
| `twitchChannel` | Логин канала Twitch (без `#` и без `https://`) | *(пусто)* |
| `youtubeMode` | `Вручную (Video ID + ключ)` или `Вход через Google (авто)` | `Вручную (Video ID + ключ)` |
| `youtubeVideoId` | Video ID текущей трансляции YouTube (режим "Вручную") | *(пусто)* |
| `youtubeApiKey` | Твой API-ключ YouTube Data API v3 (режим "Вручную") | *(пусто)* |
| `googleClientId` | OAuth Client ID типа "TV и устройства с ограниченным вводом" (режим "Вход через Google") | *(пусто)* |
| `direction` | `Новые снизу` или `Новые сверху` | `Новые снизу` |
| `fontSize` | Размер шрифта, px | `18` |
| `maxMessages` | Сколько последних сообщений держать на экране | `40` |
| `bgOpacity` | Непрозрачность фона карточки, % (0 — полностью прозрачно) | `55` |
| `showPlatformIcons` | Показывать значок площадки (🟣 Twitch / 🔴 YouTube) | `true` |
| `showBadges` | Показывать бейджи (модератор/VIP/подписчик и т.д.) | `true` |
| `showTimestamps` | Показывать время сообщения | `false` |
| `textColor` | Цвет текста сообщений | `#f4f0ea` |

Пример ссылки с параметрами (режим "Вручную"):
```
index.html?twitchChannel=my_channel&youtubeMode=Вручную+(Video+ID+%2B+ключ)&youtubeVideoId=dQw4w9WgXcQ&youtubeApiKey=AIzaSy...&direction=Новые+снизу&fontSize=18&maxMessages=40&bgOpacity=55&showBadges=true
```

Пример ссылки с параметрами (режим "Вход через Google"):
```
index.html?twitchChannel=my_channel&youtubeMode=Вход+через+Google+(авто)&googleClientId=1234567890-abc.apps.googleusercontent.com
```

Можно использовать только одну площадку — просто оставь параметры второй пустыми.

## Известные ограничения

- Бейджи Twitch/YouTube показаны упрощённо — эмодзи-значком с подсказкой при
  наведении, а не настоящей картинкой бейджа (загрузка настоящих бейджей требует
  дополнительной авторизации через Twitch Helix API — вне рамок этого виджета).
- Эмодзи и картинки эмоутов Twitch подставляются автоматически (из тегов IRC),
  сторонние эмоуты (7TV/BTTV/FFZ) — нет.
- Video ID YouTube трансляции (режим "Вручную") нужно обновлять вручную на
  каждый новый эфир.
- При очень активном чате и маленькой дневной квоте ключа YouTube-сообщения могут
  приходить с задержкой — Twitch на это не влияет и продолжает работать в
  реальном времени.
- Режим "Вход через Google" технически зависит от того, разрешит ли Google
  прямые запросы к своим OAuth-серверам из статического файла без бэкенда —
  это не 100%-но гарантированное поведение (см. раздел выше). Если не
  сработает — используй режим "Вручную".
- В режиме "Вход через Google" вход отдельный для каждого браузерного
  контекста — то есть отдельно для OBS-источника и отдельно для окна самого
  FoxFire Hub, если пользуешься обоими.
